# Repository instructions

## Scope

- This repository owns the `xldif` CLI, which compares two Excel workbooks
  (values, formulas, formatting, workbook objects) with content-aligned rows
  and columns, and the `xldif` agent skill that drives it.
- `crates/xldif` owns every workbook rule and has no process I/O.
  `crates/xldif-cli` adapts it to the process contract.
  `crates/xldif-fixtures` writes synthetic test workbooks and is used only by
  tests.
- `skills/` holds the published skill catalog: `skills/<name>/SKILL.md`,
  `agents/openai.yaml`, and directly linked resources. Repo-local
  `.agents/skills/` and `.claude/skills/` are generated by `sjskills` from
  `sjskills.toml`; never edit those copies.

## Read first

- `PLAN.md` for decisions, the milestone in progress, and the next action.
- `ARCHITECTURE.md` for boundaries, invariants, and the JSON process
  contract.
- `README.md` for commands and building.

## Confidentiality

- `fixtures/private/` holds real audit workbooks and is git-ignored. Their
  contents, file names, sheet names, sizes, and derived values must never be
  committed, quoted in docs, tests, or commit messages, or uploaded.
- Public tests use only synthetic workbooks built by `crates/xldif-fixtures`
  or hand-made files with invented content.

## Working rules

- The process contract is a compatibility surface: one newline-terminated
  stdout document per invocation, stable `error.code` values, and exit codes
  0/1/2. Add fields without removing old ones; a breaking change needs a new
  `metadata.contract`. Keep its shape aligned with `../dsdai`'s `dsd`.
- Fixture formulas always carry a cached result (`xldif_fixtures::formula`).
- A file-format fact is verified only after it has been observed in an
  Excel-saved workbook. Until then, mark it as unverified in the plan or the
  code.
- A behavior change needs a test: CLI behavior in
  `crates/xldif-cli/tests/cli.rs`, library behavior next to the code.

## Release

- `.github/workflows/release.yml` builds and publishes archives when a `v*`
  tag matching the workspace version in `Cargo.toml` is pushed. The
  workspace version is the version authority. Never push tags or create
  releases as part of ordinary implementation work.

## Validation

- `python scripts/check.py` runs skill package checks, `cargo fmt`, `clippy`
  (pedantic, warnings denied), `test`, and a CLI smoke run of the built
  executable. From M1, when `fixtures/private/` exists, it also runs the
  private corpus without printing content; until then it only counts it.
- Run it after any change to code, the skill, or fixtures.
